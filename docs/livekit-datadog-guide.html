The problem we started with

Symptom

Calls happened, but nothing inside LiveKit appeared in Datadog, and tool calls were completely invisible. Only the worker's background WebSocket keepalives showed in APM.

Why the "obvious" paths fail

① LiveKit's OTEL→ddtrace bridge silently drops the spans. ② The Agent's OTLP receiver wouldn't start. ③ ddtrace can't auto-instrument openai v2 (which LiveKit requires). All three dead-ended.

What made it work

1 · LLM Obs bridge

Instrument the agent's own hooks with the ddtrace LLMObs SDK: wrap each @function_tool in LLMObs.tool(...) and the model turn in LLMObs.llm(...). Ships over the proven APM intake (:8126).

2 · Thread job executor

LiveKit runs each call in a forked subprocess whose telemetry never exported. JobExecutorType.THREAD runs calls in the main, ddtrace-instrumented process — so the spans flush.

The setup (what to keep)

In the worker (agent.py)

from ddtrace.llmobs import LLMObs
LLMObs.enable(ml_app="livekit-loan-agent")          # at import, in the main process

class LoanAgent(Agent):
    async def llm_node(self, *a, **k):               # wrap each model turn
        with LLMObs.llm(model_name="gpt-4o", name="llm",
                        model_provider="azure_openai", session_id=self._sid) as s:
            ...; async for chunk in super().llm_node(*a, **k): yield chunk

    @function_tool
    async def check_loan_eligibility(self, ctx, annual_income, requested_amount=0):
        with LLMObs.tool(name="check_loan_eligibility", session_id=self._sid) as s:
            ...                                       # tool call now visible

# THREAD executor: run calls in the instrumented process so spans flush
cli.run_app(WorkerOptions(entrypoint_fnc=entrypoint,
                          job_executor_type=JobExecutorType.THREAD))

Verify in 3 steps

  1. Worker logs registered worker, then on a call LLM Obs bridge active — session_id=….
  2. Make a call (real client or the LiveKit Agents Playground). Ask for a loan and give an income so a tool fires.
  3. LLM Observability → filter @ml_app:livekit-loan-agent → open the session → see the tool, llm, and tts spans with arguments and tokens.
The one gotcha: a worker can run for days with zero data — LiveKit only traces once a participant joins a room. An idle registered worker is normal; you need an actual call before any trace exists.
